Reports move_uploaded_file() in a function that never checks the file type (CWE-434, Unrestricted Upload of File with Dangerous Type). An uploaded .php file in a web-accessible folder is remote code execution.

Vulnerable

$target = $dir . '/' . $_FILES['font']['name'];
move_uploaded_file( $_FILES['font']['tmp_name'], $target );

Fixed

$check = wp_check_filetype_and_ext( $_FILES['font']['tmp_name'], $_FILES['font']['name'], array( 'woff2' => 'font/woff2' ) );
if ( ! $check['ext'] ) {
    wp_die( 'File type not allowed' );
}
move_uploaded_file( $_FILES['font']['tmp_name'], $dir . '/' . sanitize_file_name( $_FILES['font']['name'] ) );

Any type check in the same function silences the inspection: wp_check_filetype(_and_ext), wp_handle_upload(), an image or MIME sniff, or an extension read with pathinfo(). A destination with a fixed literal extension is not reported. Prefer wp_handle_upload().

Rule WP-011 · CWE-434 · see the kassi-wp-rules repository for references.
