Reports request data ($_GET, $_POST, $_REQUEST, $_COOKIE, REST parameters) that reaches PHP header() without removing CR/LF (CWE-113, HTTP response header injection / response splitting).

A carriage return or line feed left in that value lets an attacker add their own response headers or split the response — setting cookies, poisoning caches, or injecting a second response body. This is effective on PHP 7 and earlier, where header() did not reject line breaks.

Vulnerable

header( 'X-Status: ' . $_GET['status'] );

Fixed

// sanitize_text_field() removes line breaks.
$status = sanitize_text_field( wp_unslash( $_GET['status'] ) );
header( 'X-Status: ' . $status );

sanitize_text_field(), sanitize_key() and an (int) cast remove the line breaks and are treated as safe. esc_url_raw(), esc_html() and str_replace() do not, on their own, remove an interior CR/LF and are not accepted. A Location: header built from request data via wp_redirect() is reported by WP-008 (open redirect) instead. A capability check in the same function lowers the severity. The flow is followed inside one function only.

Rule WP-018 · CWE-113 · see the kassi-wp-rules repository for references.
