Reports a REST route registered with register_rest_route() that anyone can call:

  • an endpoint with no permission_callback, or
  • a state-changing endpoint (any method other than GET/HEAD) whose callback always allows access: '__return_true', or a closure that only returns true.

Without a real permission check, unauthenticated visitors can call the route (CWE-862, Missing Authorization). Example: CVE-2022-0218 (WP HTML Mail), where anyone could overwrite the theme settings.

Vulnerable

register_rest_route( 'my-plugin/v1', '/settings', array(
    'methods'             => 'POST',
    'callback'            => 'my_plugin_save_settings',
    'permission_callback' => '__return_true',
) );

Fixed

register_rest_route( 'my-plugin/v1', '/settings', array(
    'methods'             => 'POST',
    'callback'            => 'my_plugin_save_settings',
    'permission_callback' => function () {
        return current_user_can( 'manage_options' );
    },
) );

An always-true callback on a write route is reported as a weak warning: intentionally public routes (form submissions, signed webhooks) are declared the same way, and stay safe only if the handler authenticates the request itself. Check that it does.

A read-only route with no permission_callback is also reported as a weak warning. If the route is meant to be public, declare 'permission_callback' => '__return_true' explicitly; a quick-fix does this, and it does not change behaviour. Check that the handler does not write anything: a route declared as GET can still delete data (CVE-2026-9172).

The inspection stays silent when it cannot prove the shape: endpoint arrays built elsewhere, computed keys, methods that cannot be resolved, or a callback that is any other function.
