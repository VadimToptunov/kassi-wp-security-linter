Reports request data ($_GET, $_POST, $_REQUEST, file names from $_FILES, REST parameters) that reaches the path argument of unlink(), file_get_contents(), readfile(), fopen(), copy(), rename(), file_put_contents(), wp_delete_file() or include/require (CWE-22, Path Traversal).

A value like ../../wp-config.php lets an attacker read, overwrite, delete or execute files outside the intended directory.

Vulnerable

$file = sanitize_text_field( wp_unslash( $_POST['file'] ) );
unlink( WP_CONTENT_DIR . '/uploads/myplugin/' . $file );

Fixed

$file = sanitize_file_name( wp_unslash( $_POST['file'] ) );
unlink( WP_CONTENT_DIR . '/uploads/myplugin/' . $file );

sanitize_text_field() and str_replace( '../', '', … ) do not prevent traversal. basename(), sanitize_file_name(), realpath(), and an allow-list (in_array) or validate_file() check do. The flow is followed inside one function only.

Rule WP-007 · CWE-22 · see the kassi-wp-rules repository for references.
