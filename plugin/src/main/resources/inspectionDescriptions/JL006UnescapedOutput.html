Reports Joomla request data (raw superglobals, and the JInput getters getRaw()/getHtml()) that is echo/print-ed through assignments, concatenation or string interpolation without htmlspecialchars(), $this->escape() or a numeric cast (CWE-79, reflected Cross-Site Scripting).

htmlspecialchars()/$this->escape() and $input->getInt()/getUint()/getFloat() make a value output-safe. The filter-typed readers $input->get() (default cmd), getCmd() and getWord() strip the HTML metacharacters, so they are not reported.

Vulnerable

$q = $app->input->getRaw('q');
echo '<p>You searched for: ' . $q . '</p>';

Fixed

$q = $app->input->getRaw('q');
echo '<p>You searched for: ' . htmlspecialchars($q, ENT_QUOTES) . '</p>';

Reflected flows only, followed inside one function (or template top level). Values read back from the database (stored XSS) are not tracked. A CSRF token verified in the same function makes the finding weak.

Rule JL-006 · CWE-79 · see the kassi-wp-rules repository for references.
