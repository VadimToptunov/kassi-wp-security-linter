Reports request data ($_GET, $_POST, $_REQUEST, $_COOKIE, REST parameters) that reaches the $headers argument of wp_mail() or PHP mail() without removing CR/LF (CWE-93, email header injection).

A carriage return or line feed left in that value lets an attacker add their own headers — a Bcc:/Cc: to an arbitrary recipient, or a forged From: — turning the site into an open relay for spam or phishing.

Vulnerable

$headers = 'Reply-To: ' . $_POST['email'];
wp_mail( $to, $subject, $body, $headers );

Fixed

// sanitize_text_field() and sanitize_email() strip line breaks.
$headers = 'Reply-To: ' . sanitize_email( $_POST['email'] );
wp_mail( $to, $subject, $body, $headers );

sanitize_text_field() and sanitize_email() remove the line breaks and are treated as safe. trim(), str_replace(), wp_strip_all_tags() and sanitize_textarea_field() do not remove an interior CR/LF and are not accepted. Only the headers argument is inspected; a capability check in the same function lowers the severity. The flow is followed inside one function only.

Rule WP-017 · CWE-93 · see the kassi-wp-rules repository for references.
