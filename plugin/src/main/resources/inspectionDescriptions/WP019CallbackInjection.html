Reports request data ($_GET, $_POST, $_REQUEST, $_COOKIE, REST parameters) that reaches the callable argument of call_user_func() or call_user_func_array() (CWE-94, arbitrary function invocation).

The attacker then chooses which PHP function runs — often remote code execution (for example calling system, assert, or a sensitive WordPress function).

Vulnerable

$callback = sanitize_text_field( $_POST['callback'] );
call_user_func_array( $callback, $args );

Fixed

$callback = sanitize_text_field( $_POST['callback'] );
$allowed  = array( 'my_plugin_get_cats', 'my_plugin_get_tags' );
if ( ! in_array( $callback, $allowed, true ) ) {
    wp_send_json_error( 'Invalid callback.' );
}
call_user_func_array( $callback, $args );

There is no string sanitiser that makes a request-chosen callable safe — sanitize_text_field() / sanitize_key() clean the string but do not stop it from naming a dangerous function, so they are not accepted. The clean paths are an in_array() allow-list of the callable against known callbacks, or a literal / non-request value. A capability check in the same function lowers the severity. The flow is followed inside one function only.
