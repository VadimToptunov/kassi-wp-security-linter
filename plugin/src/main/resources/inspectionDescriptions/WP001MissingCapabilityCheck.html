Reports an AJAX (wp_ajax_*) or admin_post_* handler that changes state (options, users, posts, database rows, files, plugins) without calling current_user_can() (CWE-862, Missing Authorization).

These hooks only require a logged-in user. Without a capability check, any subscriber can trigger the action.

Vulnerable

add_action( 'wp_ajax_myplugin_save', 'myplugin_save' );
function myplugin_save() {
    check_ajax_referer( 'myplugin_save' );
    update_option( 'myplugin_settings', wp_unslash( $_POST['settings'] ) );
    wp_send_json_success();
}

Fixed

function myplugin_save() {
    check_ajax_referer( 'myplugin_save' );
    if ( ! current_user_can( 'manage_options' ) ) {
        wp_send_json_error( null, 403 );
    }
    update_option( 'myplugin_settings', wp_unslash( $_POST['settings'] ) );
    wp_send_json_success();
}

The handler must be in the same file as its add_action() call. A capability check in the handler, or in a same-file helper it calls, silences the inspection. Updating the current user's own meta is not reported. Handlers that are also registered on a nopriv hook are covered by WP-003.
