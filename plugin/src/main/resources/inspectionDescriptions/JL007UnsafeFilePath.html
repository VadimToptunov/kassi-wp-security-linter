Reports Joomla request data (raw superglobals, and the JInput getters getString()/getRaw()/getPath(), which keep directory separators) that reaches an include/require or the path argument of readfile()/file_get_contents()/fopen() through assignments, concatenation or string interpolation, without basename(), realpath() or an allow-list (CWE-22, Local File Inclusion / Path Traversal).

basename()/realpath(), the slash-stripping readers $input->get() (default cmd)/getCmd()/getWord(), and numeric casts defeat traversal. Joomla's static JPath::clean()/ JFile::makeSafe() are also treated as safe.

Vulnerable

$view = $app->input->getString('view');
require_once JPATH_COMPONENT . '/views/' . $view . '/view.html.php';

Fixed

$view = $app->input->getCmd('view');   // cmd filter strips '/' and '..'
require_once JPATH_COMPONENT . '/views/' . basename($view) . '/view.html.php';

The flow is followed inside one function only. A capability check (authorise()) in the same function makes the finding weak (only privileged users reach the sink). A static JFile::read() sink is not matched in this version.

Rule JL-007 · CWE-22 · see the kassi-wp-rules repository for references.
