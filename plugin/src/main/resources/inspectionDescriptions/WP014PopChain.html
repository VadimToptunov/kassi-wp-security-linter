Reports a PHP object-injection chain (CWE-502): a file that holds both an attacker-reachable deserialization sink and a POP gadget — a class whose magic method (__destruct, __wakeup, __toString, __call, __get, __set) performs a dangerous operation (file write or delete, $wpdb SQL, exec/include, an outbound HTTP request, or an option write). Once an attacker can inject an object through the sink, the gadget completes the exploit.

The sink is either unserialize()/maybe_unserialize() of request data, or a file operation on a request-derived path that can carry a phar:// wrapper (PHAR deserialization).

Vulnerable

// sink: a request-controlled path reaches a file op (phar:// → deserialization)
$file = $_GET['tpl'];
if ( file_exists( $file ) ) { /* ... */ }

// gadget in the same (or any co-installed) plugin
class Cache_Writer {
    public $path;
    public function __destruct() { unlink( $this->path ); } // attacker-chosen file
}

Fixed

$file = realpath( $dir . '/' . basename( $_GET['tpl'] ) );
if ( $file && str_starts_with( $file, $dir ) && file_exists( $file ) ) { /* ... */ }
// unserialize( $data, array( 'allowed_classes' => false ) ) for the unserialize sink

The whole-project report and the headless corpus run pair a sink in one plugin with a gadget in any co-installed plugin (or WP core) and rank the chains by reachability and gadget danger. This inspection is the single-file, same-plugin projection: it stays silent unless both halves are in view, so a lone sink (WP-009's concern) or a harmless magic method does not fire.

Rule WP-014 · CWE-502 · see the kassi-wp-rules repository for references.
