Reports request data ($_GET, $_POST, $_REQUEST, $_COOKIE, WP_REST_Request parameters, …) that reaches the SQL text of a $wpdb query method (query, get_results, get_var, get_row, get_col) through assignments, concatenation or string interpolation, without $wpdb->prepare() placeholders (CWE-89, SQL Injection).

sanitize_text_field() and wp_unslash() do not make a value safe for SQL. Input concatenated into the format string of prepare() is reported too: prepare() escapes only the values passed for its placeholders.

Vulnerable

$id = sanitize_text_field( $_GET['id'] );
$row = $wpdb->get_row( "SELECT * FROM {$wpdb->prefix}orders WHERE id = '$id'" );

Fixed

$id = absint( $_GET['id'] );
$row = $wpdb->get_row(
    $wpdb->prepare( "SELECT * FROM {$wpdb->prefix}orders WHERE id = %d", $id )
);

The flow is followed inside one function only. The inspection stays silent when the value passes through a function it does not know, comes from a parameter, or is cast to a number.

Rule WP-005 · CWE-89 · see the kassi-wp-rules repository for references.
