Reports Joomla request data (superglobals, and the JInput getters getString, getRaw, getCmd, …, including the bare $input->get() / $app->input->get()) that reaches the SQL text of $db->setQuery() (or $db->query()/$db->q()) through assignments, concatenation or string interpolation, without $db->quote()/ $db->escape() or an integer cast (CWE-89, SQL Injection).

$db->quote(), $db->escape() and (int)/$input->getInt() make a value SQL-safe; getString/getRaw/getCmd do not. $params->get() (a Registry value, not request input) is not reported.

Vulnerable

$alias = $input->getString('alias');
$db->setQuery("SELECT * FROM #__content WHERE alias = '" . $alias . "'");

Fixed

$alias = $input->getString('alias');
$db->setQuery("SELECT * FROM #__content WHERE alias = " . $db->quote($alias));

The flow is followed inside one function only. The inspection stays silent when the value passes through a function it does not know, comes from a parameter, or is cast to a number.

Rule JL-005 · CWE-89 · see the kassi-wp-rules repository for references.
